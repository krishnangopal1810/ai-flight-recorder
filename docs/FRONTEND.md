# Frontend

The inspector is a guided investigation workspace for one failed agent run. Its stable routes are `/runs`, `/runs/:runId/understand`, `/runs/:runId/reproduce`, `/runs/:runId/compare/:candidateId`, `/jobs`, and `/jobs/:jobId`; legacy capsule links open the corresponding Understand stage. The UI uses the generated OpenAPI types and never accesses storage or reconstructs replay/diff domain decisions.

The normal journey is an explicit five-step loop: `Add a run -> Inspect trace -> Change one value -> Replay pipeline -> Compare runs`. A persistent numbered workflow shows the current step. The selected operation panel is the bridge from inspection to experimentation: model calls expose “Change model input” and “Change model output”; tool and retriever calls expose “Change tool output.” After replay, the service verifies that the candidate actually recorded the edited value. A verified handoff opens the comparison on “Your controlled change”; a failed substitution is labelled as not applied and opens failure evidence instead. Capsule IDs, manifests, digests, boundary occurrence, and alignment internals remain inside explicit technical details.

Add Run is a guided capture flow rather than an SDK documentation page. It first explains the result—one real execution opens as a visual model/tool timeline—then asks whether the agent is on the current computer, already running elsewhere, or available as a recording file. The local path checks whether tracing exists before it shows a command; an unsure user gets a short Python auto-instrumentation path instead of a command that cannot work. The running-agent path names the project, copies the destination, authorization, and opt-in settings together, and explains them in plain language. Copying either setup starts polling for the next recorded run so it opens automatically. Replay-specific boundaries are optional, collapsed, and explicitly identified as a step that must happen before recording only when the user needs editable, safe replay.

Every opened run provides a **Download recording** action that creates its portable `.tar.zst` bundle with a service-and-date filename. The import path explains the reciprocal workflow—open Runs, select a run, and download it—before mentioning the CLI fallback. Integrity implementation such as digest trees is never user-facing; import says that Flight Recorder checks the file is complete and has not been changed or damaged before adding it.

Playback is passive. The failure path opens by default, unrelated branches stay collapsed, and individual payload bytes are fetched only after the user requests them. Every reference preserves its `available`, `missing`, `corrupt`, or `unavailable` state; digest-invalid bytes are never rendered. Model configuration, artifacts, evaluations, provenance, and integrity remain available in the collapsed Recorded context section. Evidence, computed observations, and hypotheses use distinct labels and types.

The experiment editor loads verified recorded JSON for one selected boundary. The plan labels that value as Changed, substituted tools as Recorded, and allowed model calls as Live read. Replay progress renders durable named stages, never estimated percentages. A completed replay links directly to a hydrated side-by-side comparison; the resolution screen saves the evidence as a regression and provides a CI command.

A blocked replay never leads with completeness codes or substitution terminology. It names the affected model/tool call, states what input or output is absent, explains that replay stops to avoid guessing or contacting the real dependency, and gives the exact re-recording fix. Raw codes and backend diagnostics are available only under Technical details. The primary recovery action returns to the affected timeline operation; the secondary action starts a new recording.

The inspector contains no demo entry point, built-in token, seeded-project behavior, or fixture-specific replay default. `make dev-up` may run the instrumented agent in `examples/investigation-agent`, but its genuine failed run and isolated replay enter through normal product contracts and are rendered exactly like any user-recorded investigation. Synthetic fixtures are limited to automated edge-state tests such as missing or corrupt evidence and never ship as product behavior.

Use semantic HTML, keyboard-operable controls, visible focus, 44px touch targets, and deterministic data. Playwright retains DOM, screenshots, traces, and video for the real-agent journey plus connection, incompleteness, partial playback, comparison, and job-stage states.
